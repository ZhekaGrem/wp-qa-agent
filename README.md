# 🚀 WordPress QA Agent

**WordPress QA Agent** — це сучасний захищений інструментарій та автономна система для автоматизованого тестування WordPress та WooCommerce за допомогою AI-агентів (Claude Code, Gemini CLI, Cursor, Copilot) та **Playwright Test Agents**.

---

## 📌 Основні можливості

- 🛡️ **Захист середовища (Environment Guard):** Автоматичне блокування руйнівних дій та тестування на продакшені за замовчуванням.
- ⚡ **3 Модульні режими тестування:** Виконує тільки ті перевірки, які потрібні зараз (без зайвого очікування та витрати токенів).
- 🧠 **Playwright Test Agents (v1.56+):** Автоматичне дослідження сайту (Planner), генерація спеків (Generator) та інтерактивна пропозиція виправлень тестів (Healer).
- 📊 **Трекінг дефектів та каталогу:** Збереження постійної історії тестів (`qa/test-catalog.json`) та життєвого циклу багів (`qa/findings.json`).
- 🔌 **Підтримка MCP (Model Context Protocol):** Пряма інтеграція з Playwright MCP, Chrome DevTools MCP та Filesystem MCP.
- 💻 **Кросплатформеність:** Працює на Node.js без обов'язкової залежності від Linux Bash (повна підтримка Windows PowerShell).

---

## 🛠️ Встановлення та Налаштування

### 1. Клонування або копіювання проекту
Скопіюйте вміст директорії `wp-qa-agent` у свій проєкт або використовуйте як окремий репозиторій.

### 2. Встановлення залежностей
```bash
npm install
```

### 3. Створення конфігураційного файлу
Скопіюйте приклад конфігурації змінних середовища та вкажіть ваш URL для тестування:
```bash
cp config/wordpress-qa.example.env .env.qa
```
*Відредагуйте `.env.qa`, вказавши `QA_BASE_URL` (наприклад: `http://localhost:9400` або `https://staging.example.com`).*

### 4. Підключення MCP серверів (для Claude Code / AI-агентів)
```bash
# Playwright MCP (дослідження браузером)
claude mcp add playwright -- npx -y @playwright/mcp@latest

# Chrome DevTools MCP (аналіз консолі та мережевих помилок)
claude mcp add chrome-devtools -- npx -y chrome-devtools-mcp@latest

# Filesystem MCP (безпечна робота з артефактами)
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem "$(pwd)"

# Перевірка підключених MCP
claude mcp list
```

### 5. Первинна валідація налаштувань
```bash
npm run qa:setup
```

## 🎮 Команди — Що роблять і для чого

Всі команди розроблені для швидкого запуску через `npm run`:

| Команда | Опис та призначення | Коли використовувати |
|---|---|---|
| **`npm run qa:setup`** | **Перевірка інструментарію та валідація:** Перевіряє версії Node.js, npm, Playwright, PHP, Composer, WP-CLI та авто-створює необхідну структуру папки `qa/`. | При першому запуску або після оновлення залежностей. |
| **`npm run qa:fast`** | ⚡ **Швидкий режим (Fast Mode):** Виконує перевірку Guard → підготовку фікстур → запуск E2E Playwright тестів → перевірку стану БД тільки для мутаційних дій → генерує підсумковий звіт. | Для щоденного smoke/E2E тестування під час розробки. |
| **`npm run qa:update`** | 🔄 **Режим оновлень (Update Mode):** Виконує Guard → Snapshot версій → критичні E2E тести → візуальне порівняння скріншотів (Visual Regression) → звіт. | Перед та після оновлення плагінів, тем або ядра WordPress. |
| **`npm run qa:full`** | 🛡️ **Повний аудит (Full Mode):** Проганяє Guard → статичний аналіз коду (PHPCS, ESLint, Stylelint) → PHPUnit типи → Plugin Check → всі E2E тести → Axe A11y (доступність) → Visual → звіт. | Перед релізом проєкту або під час повного QA аудиту. |
| **`npm run qa:plan`** | 🗺️ **Режим планування (Planner Mode):** Викликає Playwright Planner для дослідження сайту → створює `test-plan.md` з унікальними `testId` → чекає підтвердження → Generator створює `.spec.ts` тести. | При підключенні нового сайту або додаванні великих фіч. |
| **`npm run qa:html`** | 🌐 **W3C HTML Валідація:** Окремий опціональний перевіряльник згенерованого HTML на відповідність стандартам W3C. | За потреби перевірки семантики та валідності HTML. |
| **`npm test`** | **Прямий запуск Playwright:** Запускає `npx playwright test` у звичайному режимі. | Для точкового запуску окремих `.spec.ts` файлів. |
| **`npm run agents:init`**| **Ініціалізація Playwright Agents:** Конфігурує офіційні агенти Playwright у проєкті. | Після первинної інсталяції Playwright. |

## 📂 Структура артефактів та результатів (`qa/`)

Всі результати тестування зберігаються в папці `qa/`:

```text
qa/
├── test-catalog.json          # Постійний реєстр усіх тестів (automationStatus, lastResult)
├── findings.json              # Реєстр дефектів та їхній життєвий цикл (OPEN -> VERIFIED -> CLOSED)
├── status.md                  # Згенерований огляд стану QA для команди
└── runs/
    └── <run-id>/              # Ізольована папка конкретного запуску
        ├── run.json           # Головний маніфест з агрегованими результатами
        ├── playwright-results.json # Сирі результати Playwright
        ├── report.md          # Короткий підсумковий Markdown-звіт
        ├── raw/               # Логи PHPCS, PHPUnit, Axe (зчитуються AI лише за потреби)
        ├── screenshots/       # Скріншоти помилок та візуальних порівнянь
        └── traces/            # Traces Playwright для відладки
```

---

## 🧠 Спеціальні скілли у папці `skills/`

1. **`wordpress-environment-guard`** — пре-флайт перевірка безпеки (блокує руйнівні дії на прод-сайтах).
2. **`wordpress-fixture-manager`** — створення та чистка тестових даних (користувачі, товари WooCommerce, купони).
3. **`wordpress-update-smoke`** — порівняння стану "до" та "після" оновлень.
4. **`wordpress-state-verifier`** — перевірка реальних змін у БД WordPress для мутаційних тестів (checkout, publish, stock).
5. **`wordpress-test-tracker`** — оновлення каталогу тестів та баг-трекера.
6. **`wordpress-evidence-reporter`** — збір фінального звіту.
7. **`playwright-test-planner`** — обгортка для роботів Planner, Generator, Healer.

---

## 🔒 Модель Безпеки

- **Продакшен захищено:** Будь-які записи, модифікації бази даних, оплати чи оновлення на продакшені заборонені за замовчуванням.
- **Підтвердження виправлень (Human Gate):** Healer не застосовує зміни у коді тестів авто-режимом без згоди розробника.
- **Закриття дефектів:** Зміну статусу багу на `CLOSED` здійснює тільки людина.
